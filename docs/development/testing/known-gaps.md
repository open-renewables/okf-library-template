# Known gaps

Behaviour not covered by an automated test at the end of build phase P1, with the reason and what closes it. Recorded here instead of skipping a test silently (conventions, Tests). Verification items (V-nn) are in SDD §15; OD-n and PP-n are in `plan/archive/2026-11-p1-core-tooling/plan.md`.

| # | Gap | Reason | Closed by |
| --- | --- | --- | --- |
| G1 | **Cross-system run.** Every test ran on Windows 11 only, on Python 3.11, 3.12 and 3.14. Path separators, line endings from a macOS or Linux checkout, symlink-less checkouts and zlib differences are untested on those systems | There is no hosted CI before P2 (plan OD-9). `.gitattributes`, CRLF tests and `pathlib` throughout reduce the risk but do not prove it | P2 matrix on Linux, macOS and Windows (Python 3.11 and 3.14); V-12 for archives |
| G2 | **Python-Markdown divergences beyond nesting.** The validator parses with markdown-it-py; the site renders with Python-Markdown (MkDocs, Zensical). Four-space nesting is proved identical (V-02). Other constructs (lists directly after paragraphs, tables, nested footnotes, inline HTML next to Markdown) are not compared | No site build exists before P3; P0 compared only the constructs the profile uses | P3 site compatibility checks on the pilot bundle (FR8.2) |
| G3 | **GitHub scroll targets for explicit anchors.** V-01 confirmed that `<a id>` ids resolve and are lower-cased on GitHub, but not that GitHub scrolls to the id in every placement (before a heading, inside a heading, non-ASCII or parenthesised terms). Check 4 tests that an anchor exists and compares fragments without regard to case; it does not know where a browser lands | Needs a live GitHub rendering; the Markdown API was blocked in P0. `OKF404` also does not tie an id to a particular heading, because the SDD does not say where the anchor sits | A manual check on the pilot library in P4, or an SDD rule on anchor placement |
| G4 | **Hand edits to revision history.** FR3.4 asks that a hand edit fail check 3, but content alone cannot show who wrote a line. P1 enforces the line grammar (`OKF314`) and, against a base, that history is only appended to (`OKF315`). A hand edit that appends a well-formed line passes; a change with no base (a plain local run) cannot detect a deleted or altered line (PP-6) | Proving authorship needs signed lines or the platform record, which would change I-08 | P2 revision writer and the push-to-`main` run; a stronger rule only if the owner asks (PP-6) |
| G5 | **`OKF118` and `OKF119` proved by unit tests only.** `OKF118` concerns Attested Computation contract fields, a type the template profile does not declare. `OKF119` covers a message the mapper does not know, and the pinned script never emits one. A fixture would have to forge the vendored validator's output | The unreachable branches are exactly what the unit tests in `tests/template/test_conformance.py` exercise | A library that declares such a type, or a re-pin that adds messages (the pinned-message test then fails first) |
| G6 | **Scope notes.** SDD I-07 says a folder line shows "scope from the folder's scope note", but the SDD defines no scope-note type or location. Generated folder lines carry the folder title only, and nothing tests a scope note (plan OD-1) | The design is silent; building one would be a design decision | An RFC before P3 |
| G7 | **`scan.py` and the `requirements/` export are unplaced in P1.** The confidentiality scanner, its pre-commit hook, gitleaks, pip-audit and the hash-locked `requirements/*.txt` export are not built, so there are no tests for them and the pre-commit file has no scan hook (plan OD-2, OD-3). SDD §14 names them in no P1 or P2 row | Placed in P2 by the default decisions | P2 (CI and governance) |
| G8 | **Validation-speed constraint is not a gate.** A 600-concept bundle was timed once by hand ([performance.md](performance.md)); no test or job enforces the 10 s target | `constraints.md` times it in P2 | P2 |
| G9 | **Platform behaviour.** Nothing calls a platform adapter: approval inference, stale approvals, App bypass (V-05 5a, 5c), catch-up after a dropped run, and `verified` writing have no tests beyond the pure tier rules and the publishing pre-check over supplied review data | Adapters and the revision writer are P2 | P2 golden files and recorded API responses |
| G10 | **Hooks on macOS and Linux.** The pre-commit hooks ran in Git Bash and PowerShell only (G1) | As G1 | P2 matrix |
