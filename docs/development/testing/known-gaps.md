# Known gaps

Behaviour not covered by an automated test at the end of build phase P1, with the reason and what closes it. Recorded here instead of skipping a test silently (conventions, Tests). Verification items (V-nn) are in SDD §15; OD-n and PP-n are in `plan/archive/2026-11-p1-core-tooling/plan.md`.

| # | Gap | Reason | Closed by |
| --- | --- | --- | --- |
| G1 | **Cross-system run.** Every test ran on Windows 11 only, on Python 3.11, 3.12 and 3.14. Path separators, line endings from a macOS or Linux checkout, symlink-less checkouts and zlib differences are untested on those systems | There is no hosted CI before P2 (plan OD-9). `.gitattributes`, CRLF tests and `pathlib` throughout reduce the risk but do not prove it | P2 matrix on Linux, macOS and Windows (Python 3.11 and 3.14); V-12 for archives |
| G2 | **Python-Markdown divergences beyond nesting.** The validator parses with markdown-it-py; the site renders with Python-Markdown (MkDocs, Zensical). Four-space nesting is proved identical (V-02). Other constructs (lists directly after paragraphs, tables, nested footnotes, inline HTML next to Markdown) are not compared | No site build exists before P3; P0 compared only the constructs the profile uses | P3 site compatibility checks on the pilot bundle (FR8.2) |
| G3 | **GitHub scroll targets for explicit anchors.** V-01 confirmed that `<a id>` ids resolve and are lower-cased on GitHub, but not that GitHub scrolls to the id in every placement (before a heading, inside a heading, non-ASCII or parenthesised terms). Check 4 tests that an anchor exists and compares fragments without regard to case; it does not know where a browser lands | Needs a live GitHub rendering; the Markdown API was blocked in P0. `OKF404` also does not tie an id to a particular heading, because the SDD does not say where the anchor sits | A manual check on the pilot library in P4, or an SDD rule on anchor placement |
| G4 | **Hand edits to revision history.** FR3.4 asks that a hand edit fail check 3, but content alone cannot show who wrote a line. P1 enforces the line grammar (`OKF314`) and, against a base, that history is only appended to (`OKF315`). A hand edit that appends a well-formed line passes; a change with no base (a plain local run) cannot detect a deleted or altered line (PP-6) | Proving authorship needs signed lines or the platform record, which would change I-08 | P2 revision writer and the push-to-`main` run; a stronger rule only if the owner asks (PP-6) | **(Narrowed in P2 PR 2:** `write_revision.py --check-since` reports a merged change whose concept has no line, so a deleted line is caught as `OKF901`; the push-to-`main` run that calls it comes in PR 6.)
| G5 | **`OKF118` and `OKF119` proved by unit tests only.** `OKF118` concerns Attested Computation contract fields, a type the template profile does not declare. `OKF119` covers a message the mapper does not know, and the pinned script never emits one. A fixture would have to forge the vendored validator's output | The unreachable branches are exactly what the unit tests in `tests/template/test_conformance.py` exercise | A library that declares such a type, or a re-pin that adds messages (the pinned-message test then fails first) |
| G6 | **Scope notes.** SDD I-07 says a folder line shows "scope from the folder's scope note", but the SDD defines no scope-note type or location. Generated folder lines carry the folder title only, and nothing tests a scope note (plan OD-1) | The design is silent; building one would be a design decision | An RFC before P3 |
| G7 | **(Narrowed in P2 PR 1: the tasks, tests and hook exist; the CI jobs do not yet.)** **`scan.py` and the `requirements/` export are unplaced in P1.** The confidentiality scanner, its pre-commit hook, gitleaks, pip-audit and the hash-locked `requirements/*.txt` export are not built, so there are no tests for them and the pre-commit file has no scan hook (plan OD-2, OD-3). SDD §14 names them in no P1 or P2 row | Placed in P2 by the default decisions | P2 (CI and governance) |
| G8 | **Validation-speed constraint is not a gate.** A 600-concept bundle was timed once by hand ([performance.md](performance.md)); no test or job enforces the 10 s target | `constraints.md` times it in P2 | P2 |
| G9 | **(Narrowed in P2 PR 2.)** **Platform behaviour is replayed, not live.** The `github` adapter and the revision writer are tested against responses recorded in the sandbox (stale approval, merge past the bypass, direct push, lookup order and retries) and the `git-local` adapter against scratch git repositories. A review by a code owner other than the author and a merge by someone other than the author were never recorded (one human account, plan OD-2), so those cases rest on hand-built data. Approval inference has not run on a live workflow | Live runs need the workflows (PR 6) | The exit rehearsal in the sandbox (step 15) |
| G10 | **Hooks on macOS and Linux.** The pre-commit hooks ran in Git Bash and PowerShell only (G1) | As G1 | P2 matrix |
| G11 | **Licence check covers the installed environment only.** `poe licences` reads the metadata of the locked packages installed on the machine running it, so a locked package that is not installed there (for example `colorama` on Linux, or the site stack before P3) is listed as not checked. Metadata that is only free text or an ambiguous classifier is a finding until recorded in `constraints.md` | The lock holds no licence data | The P2 matrix runs it on three systems; P3 adds the site group |
| G12 | **The gitleaks hook command is untested against the real binary.** `scan.py --gitleaks` runs `gitleaks git --pre-commit --redact --staged --verbose`, taken from gitleaks' own `.pre-commit-hooks.yaml` (v8.30.1). No gitleaks binary is installed on the development machine, so the tests use a stand-in and only check the arguments and the skip notice | Installing the binary is optional locally (QA-74) | The CI gitleaks job with the pinned binary and a planted secret (P2 PR 6) |
| G13 | **`poe audit` is not run by a test.** It needs the network and an unpinned `uvx pip-audit`; tests check only the command it builds and the exceptions it reads. One manual run on 2026-11-03 found no vulnerability in `requirements/dev.txt` | Tests must not reach the network | The CI job on lock changes and weekly (P2 PR 6) |
| G14 | **The first run records the whole history.** With no `Revision-Bot` commit on `main`, the catch-up rule reads every commit, so the first run on a library or on the template adds a line for each past change that touched a concept (the template: PR #16 in four concepts). `--since <commit>` starts later. `init_library.py` does not yet write a starting marker commit | W-05 defines catch-up from the last bot commit only | Decide in PR 5 (`init_library.py`) or at the first run on the template (PR 6) |
| G15 | **`verified` times are dates.** A revision line records only the merge date, so `verified[].at` is that date at 00:00 UTC, not the merge instant (I-08 allows a datetime; the line cannot supply one). Off by default (`write_okf_verified`) | The line grammar holds a date | Only if the grammar gains a time, which would change I-08 |
| G16 | **`git-local` has no separate merger.** The commit author is taken as the merger, so a change with no `Approved-by` trailer naming someone else is `self-approved`, never `merged without approval`. A patch applied by a maintainer for a contributor is therefore recorded as the contributor's self-approval unless the maintainer is named in `Approved-by` | I-08 describes only the trailer rule | W-12 moves a library to a platform, where the merger is known |
| G17 | **The configuration check needs the network.** `poe check-config` runs `uvx check-jsonschema` with its built-in schemas for workflows, issue forms and Dependabot, so no test runs it; tests check the commands it builds and the shape of each file (labels named by the forms, the four labels in the pull request template, owners for every path). It was run by hand on 2026-11-03: all files pass, and a planted bad form fails | Tests must not reach the network | The CI `check-config` job (P2 PR 6) |
| G18 | **Placeholders that `init_library.py` must rewrite.** `.github/CODEOWNERS` names the template's maintainer, and `.github/ISSUE_TEMPLATE/config.yml` links to `GOVERNANCE.md` in the template repository (the file arrives in P3). Nothing yet checks that an instantiated library has neither | `init_library.py` is PR 5 | The W-10 self-test placeholder check (PR 5) |
