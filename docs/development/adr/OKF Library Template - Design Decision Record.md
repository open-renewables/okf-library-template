> This record holds the design decisions for the OKF library template. It starts on 18 October 2026 with the review that aligned the template with the RE library's decisions of 17–18 October (Re risk library - design decision record, QA-01 to QA-25 and DR-17 to DR-20). Owner decisions taken in Q&A are QA-01 to QA-08; design changes adopted from the gap analysis without a separate owner question are DR-01 to DR-15. The most significant are QA-01 (profile-declared provenance, with a CI-written revision history by default and an optional OKF `verified` field) and QA-04 (body sections declared in `profile.yaml`). Assumptions T1 to T6 remain in OKF Library Template - Software Requirements Spec (formerly Design and Requirements; renamed by DR-20). A second owner Q&A on 18 October 2026, following the pre-stack gap review (G1 to G19), added QA-12 to QA-28 and DR-19. On 20 October 2026 the reference stack was adopted (DR-21) and the template's Software Design Document was created (DR-22, QA-31); the build order is template first (QA-30). On 25 October 2026 a senior engineering review of the four template documents (findings H1–H5, M1–M10 and L1–L5) was settled in owner Q&A as QA-32 to QA-51; the resulting edits were applied to the SRS, the SDD and the stack options report the same day, which also completes the SRS edits proposed by DR-23. Later the same day two further owner Q&As settled repository tooling and local-only operation (QA-52 to QA-65) and a `docs/development/` structure for the template's own documentation (QA-66 to QA-76). With QA-76 the QA- and DR- series close; new decisions are ADR files in `docs/development/adr/` (QA-68), where this record now lives as `docs/development/adr/OKF Library Template - Design Decision Record.md`.

## How to use this record

- **IDs.** QA- for decisions the owner took in Q&A review; DR- for design decisions applied without a separate owner question. IDs are never reused or renumbered. Next: QA-77, DR-25. From QA-77 onwards the QA- and DR- series are frozen: new decisions are recorded as `ADR-NNN-title.md` files in `docs/development/adr/`, starting at ADR-001 (QA-68). Existing entries stay citable.
- **Status values.** Proposed, Accepted, Superseded (name the superseding decision), Accepted (amended by …).
- **Recording a decision.** Add the row here, update the affected documents in the same change, and add a line to the change log.
- **Document names.** Live cross-references use each document's exact file name, for example `OKF Library Template - Software Requirements Spec.md`, so the files can be copied into a repository without renaming. Each document defines its abbreviations once: SRS (Software Requirements Spec), SDD (Software Design Document), DDR (this Design Decision Record) (QA-35).
- **Former document names.** Rows and change-log entries dated before 19 October 2026 use the former names: *Design and Requirements* for this template's SRS, and *Requirements and design* for the RE library's SRS (DR-20). They are kept as written.
- **Scope.** Template decisions only. Decisions specific to the RE library are in Re risk library - design decision record. Each library instantiated from the template keeps its own record in `DECISIONS.md` (DR-11).

## Current position

Several topics have been decided in steps. This summary states where each stands on 25 October 2026 and names the rows that govern it; the rows remain authoritative.

| Topic | Current position | Governing rows |
| --- | --- | --- |
| Approval | `stable` needs one approval by a human directory owner, assessed per concept. No GitHub author can approve their own pull request, so a single maintainer's self-approval is an admin merge, inferred at and after merge and recorded `self-approved`. An approval given on an earlier commit than the merged head is recorded as stale. Whether a non-author approver is required is decided when a second directory owner joins | QA-15, QA-23, QA-27, QA-29, DR-23, QA-34, QA-49 |
| Provenance | CI appends a revision-history line to each changed concept after merge, by a bot commit on `main`. Each run records every pull request merged since the last bot commit, regenerates the affected indexes in the same commit, and a release fails if any merged pull request lacks its line. CI may also write OKF `verified`, mapped so that generic OKF tools derive the same tier | QA-01, QA-17, DR-21, QA-32, QA-34 |
| Trust tier | A concept's tier is the lowest tier of its revisions since the last owner-approved `full-review` revision. Self-approved human review is shown as `human-reviewed (self)` | QA-01, QA-27, QA-34 |
| Validation | Six checks plus publishing rules; content is validated with the base branch's tooling and profile; tooling or profile changes and content changes go in separate pull requests unless labelled `profile-migration`; local runs cover checks 1–6 | DR-06, QA-25, QA-33, QA-44 |
| Licences | The template repository is wholly Apache 2.0. Each library's owner licenses its content and code, which need not be open source; CC BY 4.0 is the default content licence offered at set-up | QA-47 |
| Website | Latest release only; no public site before a library's v1.0.0; a library may have no public site. Material for MkDocs reaches end of life on 5 November 2026; the generator is decided at the end of build phase P0 | QA-20, QA-26, DR-21, QA-38, QA-47 |
| Platform | A profile declares `platform: github` or `platform: git-local`. Both are implemented for v1.0.0. In `git-local` mode validation, indexes, revision history, trust tier, staleness, bundle, release and the local site work from git and Python alone; provenance comes from commit trailers. A git-local library can move to a platform by W-12. Adapters for other git hosting platforms are a post-v1.0.0 feature | QA-58 to QA-61 |
| Developer workflow | Tooling stays copied into each library under `scripts/` and is ported by hand; tasks run with poethepoet (`uv run poe <task>`), CI calls only those tasks; `poe check` runs the lock check, ruff, mypy, validation and index check; pre-commit uses local hooks only; tests are split into `tests/template/` and `tests/library/`; Python 3.11 minimum, CI on 3.11 and 3.14; no template engine | QA-52 to QA-57, QA-62 to QA-65 |
